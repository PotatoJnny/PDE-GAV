# NS first-batch data manifests

The selection seed is fixed at `20260907`. These manifests only reference the
shared D0 files under `${PDE_GAV_SHARED_DATA_ROOT}`; they neither copy nor
modify the original data. Every `case_dir` was verified to exist when the
manifests were frozen.

| File | split | Count | Purpose |
|---|---|---:|---|
| `development_manifest.json` | `development` | 512 | Development cases for the fixed-data method |
| same file | `validation` | 512 | Per-round selection for the fixed-data method |
| `calibration_manifest.json` | `calibration` | 50 (5 per family) | Data consistency and numerical-program calibration |
| `test_draft_manifest.json` | `test_draft` | 500 (50 per family) | Common evaluation of the frozen draft programs |
| `test_final_manifest.json` | `test_final` | 1000 (100 per family) | Common evaluation of the frozen final programs; includes the 500 draft cases |

Development, selection and calibration cases come from the original
`validation` split and do not overlap. Final evaluation cases come from the
original `d0_distribution_test` split, after excluding the 128 test IDs that an
earlier Generator release audit had used. No selected case is in the
Generator's 80,000-case training split. The 1,024-case common Official set of
the framework Base/Full arms is generated by the run configuration and does not
use these final evaluation cases.

`bank_index.json` records counts, families, ID order and the SHA256 of each
manifest. `freeze_data.py` regenerates identical manifests and refuses to
overwrite different existing content. The freeze fixed the manifests and
per-case JSON metadata and checked the existence and size of the NPZ files of
all 2,074 distinct cases; it did not hash every NPZ byte. The public and hidden
NPZ files of the 50 calibration cases were hashed separately in the calibration
report.

```bash
.venv/bin/python configs/paper/ns_draft_v1/data/freeze_data.py
```

The audit scripts in this directory write their evidence under
`docs/paper/evidence/`, which belongs to the experiment archive and is not part
of this repository:

- `ns_draft_v1_data_freeze_audit.json`: files, splits and the Generator
  training/selection provenance.
- `ns_draft_v1_data_coefficient_ids_audit.json`: ID metadata read from every
  coefficient shard, checking the actual membership and order of the
  training/validation/test splits.
- `ns_draft_v1_data_calibration.json`: for the 50 calibration cases, the public
  initial condition equals the hidden first frame, and the forcing recomputed
  with the original discrete MMS formula equals the public forcing; it also
  records the hold-initial and old Stokes-approximation development diagnostics.

These data should be described as discrete manufactured problems derived from
numerical trajectories. The consistency checks use the discrete differential
operators of the original construction; they do not replace an independent NS
solver or grid and time convergence verification. The old Stokes program uses a
periodic projection followed by masking and is not a reliable reference under
obstacle boundaries.

The full 5,000-case test set was historically encoded into coefficients, but
the PCA/flow fits and checkpoint selection used train/validation. Encoding is
not training leakage, but a complete audit of historical use of these test IDs
has not been completed. Development/selection cases may intersect the
validation cases the Generator used; the recorded counts state the overlap. The
final test set is disjoint from both.

The CPU checks below were executed when the data were frozen. They refuse to
overwrite existing evidence files; a recalibration must create a new version:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv/bin/python configs/paper/ns_draft_v1/data/qualify_data.py
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv/bin/python configs/paper/ns_draft_v1/data/audit_generator_ids.py
```
